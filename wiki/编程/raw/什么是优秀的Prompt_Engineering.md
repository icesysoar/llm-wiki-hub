# 什么是优秀的Prompt Engineering

## PE的本质

Prompt Engineering是通过精心设计输入指令，引导大模型生成更准确、更稳定、更可控输出的技术与方法论。

**核心原则**: 优秀PE的目标不是"多说话"，而是"说对话"

## 为什么要写好PE

- 指令模糊 → 模型不知道真正想要什么
- 缺乏上下文 → 模型只能"猜"
- 输出不可控 → 格式混乱、重点偏移
- 结果不稳定 → 每次回答差异大

## PE的核心组成要素

### 1. 角色 (Role)
告诉模型"你是谁"
- 限定知识视角和表达风格
- 示例: "你是一名资深数据分析师"

### 2. 任务 (Task)
清楚说明"要模型做什么"
- 一个Prompt尽量只做一类核心任务

### 3. 输入信息 (Context/Input)
给模型足够但不过载的背景信息
- 数据、文本、业务背景、目标受众
- 常见错误: 要求分析但不给材料

### 4. 输出要求 (Output Constraints)
明确"想要什么样的结果"
- 格式(列表/表格/JSON/Markdown)
- 字数范围
- 语言风格
- 是否给示例

## 通用方法论

```
角色 + 目标 + 输入 + 约束 + 期望输出
```

### 示例对比

**普通写法**:
> 给我写一篇关于PE的文章

**优秀写法**:
> 你是一名熟悉大模型应用的AI技术专家。请面向初学者写一篇关于Prompt Engineering的科普文章，内容包括：1）什么是PE 2）为什么PE很重要 3）如何写一个好的Prompt。要求语言通俗易懂，结构清晰，字数约1000字，使用小标题。

## 好PE的特征

| 特征 | 说明 |
|------|------|
| 清晰 (Clear) | 没有歧义，不让模型猜意图 |
| 可控 (Controllable) | 格式、风格、范围明确，结果可复现 |
| 可复用 (Reusable) | 稍作修改可用于类似任务 |
| 面向结果 | 驱动模型完成任务，而非聊天 |

## 常见技巧

1. **分步骤**: "先思考，再输出"
2. **示例驱动**: 给1-2个示例快速对齐期望
3. **约束优先**: 与其"随便发挥"不如"明确假设条件"
4. **迭代优化**: PE是不断试错、不断收敛的过程

## 核心观点

> 模型能力决定上限，Prompt质量决定下限
> 会写PE的人等于会"指挥AI"
> 不会写PE的人只是在"碰运气"

## 与现有概念关联

- **角色提示**: 角色设定是PE核心要素之一
- **结构化提示词设计**: 通用方法论的具体实现
- **六步提问法**: 迭代优化的流程体现
