# AI Coding十大关键词

## 01 Prompt 提示词

**核心**: 写好Prompt有几个关键动作:
1. **给角色**: "你是一名熟悉FastAPI的后端工程师"
2. **说约束**: 输出格式、代码风格、禁止用哪些库
3. **给例子**: Few-shot示例，对齐期望输出格式

**习惯检验**: 写完需求后问自己:如果把这句话发给刚入职的新人，他能做对吗?

## 02 Context 上下文

**问题**: 对话历史很长时，AI开始给出前后矛盾的回答

**关键**:
- 把最重要的约定和背景放在对话开头
- 长任务拆成子任务单独开新对话
- 定期重置上下文，当AI答非所问时新开对话

## 03 Token 令牌

**影响**:
- API的收费单位
- 上下文窗口有限，装了无用Token，有用内容就被挤掉
- 省Token和提升质量是一件事

**压缩方法**:
- 精简System Prompt，删掉重复解释
- 按需传入上下文，只传相关代码片段
- 对话历史做摘要压缩

## 04 Agent 智能体

**定义**: 能自主规划并执行多步任务的AI程序

**关键**: 给Agent明确的边界和权限范围
- PRD阶段定义"Agent能做什么、不能做什么"
- 防止误删文件、提交错误分支、消耗大量API配额

## 05 RAG 检索增强生成

**核心思路**:
1. 把知识库做成向量索引
2. 查询时先检索相关内容
3. 把相关内容塞进Prompt让模型基于真实信息回答

**关键**: 知识库质量决定RAG效果上限，建知识库时间投入至少占整个项目40%

## 06 MCP 模型上下文协议

**定义**: Anthropic提出的开放标准，解决AI调用外部工具接口统一问题

**类比**: USB接口 - 任何设备插上就能用

**价值**: GitHub、Figma、Slack、数据库等都有了对应MCP Server

## 07 Fine-tuning 微调

**定义**: 用你自己的数据对预训练模型做进一步训练

**适用场景**:
1. Prompt写了很多却还是不稳定的输出风格
2. 大量高度重复格式的任务需要极低延迟
3. 专有名词和内部术语模型频繁误解

**建议**: 先把Prompt工程逼到极限，确认真的解决不了才上微调

## 08 Embedding 向量嵌入

**定义**: 把文本转成高维数值向量，让计算机能计算"语义距离"

**应用**:
- RAG能工作的基础
- 代码相似度检测
- 避免重复造轮子

## 09 CoT 思维链

**定义**: 让模型把推理过程显式写出来

**效果**: 复杂任务正确率提升40%以上

**成本**: 会输出更多Token，速度更慢、费用更高

**适用**: 复杂推理任务 | **不适用**: 简单任务

## 10 Vibe Coding 氛围编程

**定义**: 靠感觉、靠意图开发，代码是AI写的，方向是你给的

**角色变化**: 从"写代码的人"变成"验收代码的人"

**风险**: 不理解AI写的代码，埋入安全漏洞、技术债

**判断**: Vibe Coding是会写代码的人提速10倍的方式，不是不会写代码的人的捷径

## 十词关系图

```
Prompt(指令) → Context(上下文) → Token(计量)
       ↓
    Agent(行动) ← RAG(知识库) ← MCP(外部世界)
       ↓
Fine-tuning(风格固化) ← Embedding(语义索引)
       ↓
     CoT(推理可见)
       ↓
Vibe Coding(人机协作新状态)
```
