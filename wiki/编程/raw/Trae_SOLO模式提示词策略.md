# Trae SOLO模式提示词策略

## 核心转变

SOLO模式让你从"写代码的人"升级为"管AI团队的人"。

**Chat模式**: 你要告诉AI "改这里，这样改"  
**SOLO模式**: 你要告诉AI "我要什么结果，你可以自己决定怎么干，但关键节点必须让我确认"

## SOLO提示词底层心法

愿景清晰、约束明确、自主空间适度、验收标准前置。

## SOLO Builder愿景描述法模板

```
我想做一个 [产品类型]，目标用户是 [用户群体]。

核心功能包括:
- [功能1:用户能做什么]
- [功能2:包括关键交互细节]
- [功能3:特殊场景/边界处理]

技术栈偏好:
[如果有倾向就写，没有就写"请根据项目特点自行选择"]

非功能性要求:
[性能、兼容性、部署方式等，可选项]

请先输出技术选型建议和项目文件结构，等我确认后再开始生成。
```

## Plan模式标准三步法

**第一步**: 启用Plan并描述需求
```
/plan
@folder src 请在当前项目基础上实现 [功能描述]。
先输出执行计划，包括:
- 需要修改或新增哪些文件
- 每个文件的主要改动内容
- 各步骤之间的依赖关系
暂时不要修改代码。
```

**第二步**: 用自然语言调整计划

**第三步**: 授权执行
```
计划没问题，开始执行。每完成一步后暂停，展示diff等我确认。
```

## Spec模式核心结构

```
/spec

项目背景: [一两句话说明要做什么、为什么做]

核心功能模块:
- 模块A: [功能描述]
- 模块B: [功能描述]

技术约束: [必须遵守的技术限制]

非功能性需求: [性能指标、安全要求等]

优先要求: 请先生成spec.md帮我审核整体架构，通过后再细化任务列表。
```

## 子任务拆分指令

```
我要实现 [大功能名称]，请把它拆分成3-4个可以独立并行开发的子任务。

要求:
- 每个子任务有明确的文件/模块输出
- 子任务之间的共享接口先作为单独的"契约任务"完成
- 拆分后输出一个子任务清单，每个子任务用一句话描述目标
```

## 干预话术

**当AI走偏时**:
```
你当前的方向偏离了我的需求。我的核心目标是 [重申目标]，请基于此调整后续步骤。
```

**让AI暂停解释思路**:
```
先暂停，解释一下你刚才这一步的决策理由，以及接下来你打算怎么做。
```

## 验收指令模板

```
请自测你刚才实现的功能:
1. 启动项目并打开预览(如果有前端)
2. 测试核心场景 [描述1-2个关键场景]
3. 测试边界情况 [空白、最大长度、网络异常等]
4. 输出一份测试报告，包括通过情况和发现的问题

如发现问题，请先自行修复，再重新测试。
```

## 七条核心原则

1. 愿景描述从产品视角切入，技术选型交给AI自主判断
2. Plan模式先要方案再授权执行，杜绝理解偏差
3. Spec模式适合系统级项目，用大纲、任务、验收三份文档管理全过程
4. 大功能拆成独立子任务并行推进，契约先行保接口一致
5. AI跑偏时用"目标重申法"一句话纠偏，不必重新开始
6. 主动触发自测验收，让AI自己发现问题修问题
7. 跨任务协作靠契约文档，所有子任务启动前先对齐规范
