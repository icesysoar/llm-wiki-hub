# Harness Engineering: AI工程第三范式

## 三代演进

### 第一代: Prompt Engineering (2022-2024)
- **核心**: 优化单次输入的指令文本
- **技术**: 角色扮演、Few-Shot、思维链、自洽性校验
- **局限**: 单次输入信息容量有限，无法支持动态多轮决策

### 第二代: Context Engineering (2025)
- **核心**: 在正确时间给正确信息
- **技术**: RAG、上下文窗口管理、动态数据接入
- **局限**: 只解决"给什么信息"，没解决"怎么管行为"
- **效果**: Claude 3复杂任务表现提升300%+

### 第三代: Harness Engineering (2026)
- **核心**: 为AI Agent构建安全可靠的运行环境
- **本质**: 从架构层面约束模型行为、管理权限、保障执行可靠性
- **数据**: GPT-4o搭配成熟Harness系统，任务完成率是单纯Prompt+Context的4.7倍

## Harness Engineering三大维度

### 1. 增强型上下文管理
- 动态上下文调度
- 多源数据接入
- 上下文垃圾回收
- MCP (Model Context Protocol) 标准

### 2. 运行时行为约束
- **权限隔离**: 划分明确操作权限边界
- **状态管理**: 维护运行状态机
- **错误兜底**: 多层级错误捕获和重试机制

### 3. 全链路评估体系
- 单元评估: 单个能力点自动化测试
- 任务评估: 端到端效果评估
- 安全评估: 风险行为、幻觉输出专项检测

## 落地五大原则

1. **安全左移**: 安全逻辑在Harness层实现，不依赖大模型判断
2. **可观测性优先**: 完整日志、trace、监控能力
3. **人机协同设计**: 清晰人工介入点，不追求100%自动化
4. **数据飞轮思维**: 执行轨迹、人工反馈回流优化
5. **渐进式迭代**: 先核心风险点，小步快跑

## 与现有概念关联

- **系统提示词**: Harness Engineering是系统提示词工程的升级版
- **迭代交互模式**: 包含错误兜底和人机协同
- **结构化提示词设计**: 提供架构层面的约束能力
