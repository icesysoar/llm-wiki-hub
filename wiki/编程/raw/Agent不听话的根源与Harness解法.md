# Agent不听话的根源与Harness解法

## Agent失控的真相

Agent跑Demo很丝滑，但一上真实任务就开始"发疯"：
- 陷入死循环
- 无故执行危险命令
- 上下文超限崩溃
- 连续执行同一条错误命令30次
- 幻觉中执行`rm -rf ./*`

在System Prompt里加"请不要陷入死循环"，效果大概和"请不要感冒"一样有用。

**根本原因**: "调包框架"(LangChain/AutoGen)是黑盒，容易失控。框架越重，失控越狠。

## 三大失控根源

1. **工具描述过多**: 塞给模型几十个工具描述，Token全浪费在描述工具上
2. **状态黑盒**: 状态藏在内存里，想debug都不知道从哪下手
3. **边界预设不足**: 任务复杂度超过框架预设边界，Agent开始"自由发挥"

## Harness: 给大模型写微型操作系统

```
大模型 = CPU: 负责思考
上下文窗口 = RAM: 极其金贵的内存
本地操作 = 外设: 硬盘、网卡，模型的"手和脚"
```

Harness不教模型怎么想，它主要干"脏活": 内存回收、硬件调度、系统中断。

## OpenClaw三招解决Agent失控

### 第一招: 极简工具集

四原语包打天下:
- **Read**: 读文件
- **Write**: 写文件
- **Edit**: 改代码
- **Bash**: 执行命令

工具越少，上下文越干净，出错概率越低。

### 第二招: 状态外部化

强制Agent把数据写在Markdown文件里:
- 规划写在`PLAN.md`
- 进度写在`TODO.md`

状态不再是黑盒，随时可以打开、阅读、手动修改。

### 第三招: YOLO + 防御纵深

- **本地环境**: YOLO模式，让Agent自由狂奔
- **底层安全**: 检测到高危命令自动挂起等待审批
- **信任但验证**: 开发环境放手，部署到服务器自动收紧

## 为什么必须自己造轮子

- 会用框架 ≠ 理解底层逻辑
- 框架出问题时只能搜答案、改参数、碰运气
- 理解Harness逻辑 → 能看到问题本质

**核心观点**: Agent的尽头是OS。框架会变，API会变，但底层的Harness逻辑是相通的。
