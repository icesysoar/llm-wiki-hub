# Trae提示词底层逻辑与万能公式

## 为什么提示词总是不准?

**核心认知**: 提示词的本质是消除歧义的过程。每一次不准确的输出，往回追溯，一定有一个没说清楚的输入。

## Trae提示词万能公式

```
[背景/角色] + [具体任务] + [关键约束] + [输出格式]
```

## 四要素详解

### 要素一: 背景/角色

告诉AI"现在在什么场景下、你需要扮演谁"。

**不加背景**:
```
写一个处理用户数据的函数。
```
→ AI不知道"处理"是清洗、验证、脱敏还是转换格式

**加上背景**:
```
我们有一个用户注册系统。现在需要写一个函数，对用户输入的手机号做脱敏处理(中间四位变****)，用于在前端展示。
```

**角色绑定法(进阶)**:
```
你是一名资深TypeScript工程师，注重类型安全和函数纯度。请为以下需求写出实现。
```

### 要素二: 具体任务

好任务描述的三个标准:
1. **有动词，且动词精准**
   - ❌ "优化一下这个函数"
   - ✅ "将函数的嵌套if-else改写为早返回模式，并移除重复的计算逻辑"

2. **有对象，且对象明确**
   - ❌ "改一下那个页面的样式"
   - ✅ "修改Dashboard.tsx中.stats-card的padding和阴影，使其和ProfileCard组件风格统一"

3. **有边界，且边界清楚**
   - ❌ "加个登录功能"
   - ✅ "新增邮箱+密码登录入口，调用/api/auth/login接口，成功后存token到localStorage并跳转到首页，失败显示错误提示"

### 要素三: 关键约束

五种约束类型:

1. **技术约束**: "不要使用any，所有类型必须显式声明"
2. **范围约束**: "只修改auth.ts，不要动其他文件"
3. **质量约束**: "每个函数不超过30行，超过则拆分"
4. **否定约束**: "不要添加用户注册功能"
5. **安全约束**: "所有用户输入必须做trim和XSS过滤"

### 要素四: 输出格式

常用格式指令:
- "仅输出代码，不要解释"
- "用TypeScript实现，包含完整类型定义"
- "先列出改动计划，等我确认后再修改代码"
- "以Markdown表格列出所有改动文件、行号和改动描述"

## 黄金法则

**先给AI"看"，再让它"做"**

任何涉及项目文件的任务，先@注入上下文，再提需求。

**错误做法**:
```
帮我把utils.ts里的formatDate函数改成支持多种日期格式。
```

**正确做法**:
```
@file src/utils/formatDate.ts
修改formatDate函数，新增第二个可选参数format: 'short' | 'long' | 'iso'，默认short。保持原有逻辑不变。
```

**短提示词版**:
```

```
→ AI在某个函数里加了简单的try-catch，重试逻辑只写了一个函数
