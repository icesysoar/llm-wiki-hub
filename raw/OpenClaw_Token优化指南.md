# OpenClaw Token优化指南

## 核心目标

将Token使用量减少30%-50%，同时保持甚至提高代理执行质量。

## 策略1: 优化提示词工程

**错误做法**:
```
你好，我想让你帮我做一件事。其实这件事是关于市场调研的...
```
→ 模型生成冗长回复，消耗大量Output Token

**正确做法**:
```
任务:进行竞争对手价格分析
目标:提取前3名竞争对手的核心产品定价
输出格式:JSON表格，仅包含{产品名，价格，特性}
限制:不要包含介绍性文字或总结，只输出JSON
```

**效果**:
- Input Token减少约40%
- Output Token减少约60%

## 策略2: 智能管理上下文窗口

**问题**: 对话历史累积，Token消耗呈线性甚至指数增长

**解决方案**:

1. **滑动窗口**: 只保留最近的N条消息(如10条)
2. **摘要记忆**: 用小型模型定期总结旧对话，用总结替换原文

## 策略3: 根据任务复杂度选择模型

| 任务类型 | 推荐模型 | 原因 |
|----------|----------|------|
| 复杂推理、代码生成 | GPT-4o/Claude 3.5 | 高智能 |
| 数据提取、格式化 | GPT-3.5-turbo/Haiku | 速度极快，成本低 |
| 拼写检查、关键词提取 | 本地小模型/规则引擎 | 几乎零成本 |

**分层模型策略**:
- 规划器(Planner)代理: 高端模型
- 执行器(Executor)代理: 低端模型

## 策略4: 实施缓存机制

**语义缓存**: 存储之前查询和响应，新查询相似度>90%时直接返回缓存结果

**场景示例**:
- 无缓存: 100次查询 → $1.00
- 有缓存: 100次查询(60次重复) → $0.40
- **节省: 60%**

## 策略5: 优化数据处理流程

**预处理步骤**:
1. 清洗数据: 去除HTML标签、广告、导航栏
2. 分块处理: 将大文档切分成小块
3. 预过滤: 用关键词匹配先筛选相关段落

**错误示例**: 发送整个50000字网页源码给GPT-4找电话号码
**正确示例**: 用代码提取候选字符串(200字)，发给AI验证

## 策略6: 设置严格的停止条件

- **最大迭代次数**: 限制尝试次数(如最多5次)
- **时间超时**: 超过设定时间(如2分钟)强制终止
- **Token预算限制**: 设置单个任务Token上限

## 策略7: 监控与分析

建立监控仪表盘:
- 记录每个任务的Input/Output Token数量
- 识别消耗Token最多的代理或工作流
- 跟踪每次调用的成本

## 常见误区

| 误区 | 真相 |
|------|------|
| 全部使用最便宜的模型 | 可能导致任务失败率上升，需要人工重试 |
| 提示词越长AI越聪明 | 冗长提示词浪费Token，还可能让模型迷失重点 |
| 缓存太复杂不值得做 | 对于重复性高的企业工作流，ROI最高 |

## 综合优化案例

**原始流程**:
- 搜索10个网站 → 抓取全文 → GPT-4总结 → GPT-4整合
- 单次运行成本: $2.50

**优化后流程**:
- 搜索10个网站 → 预处理(节省60%Input) → Haiku总结(节省90%) → 缓存(节省40%) → 仅GPT-4整合
- 单次运行成本: $0.90
- **总节省: 64%**
